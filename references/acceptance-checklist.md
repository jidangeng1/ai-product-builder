# Acceptance Checklist

## Build
- App installs and starts without blocking errors.
- No secrets are committed.
- README contains exact local run instructions.

## UX
- Primary journey is discoverable.
- Buttons used in the demo work.
- Required loading, empty, success, and error states are understandable.
- No obvious broken layout at common laptop width.

## Product
- The core problem is demonstrated end to end.
- Business rules are deterministic where they should be.
- AI suggestions are distinguishable from confirmed human decisions.
- Demo data is explicitly fictional/anonymized.

## AI
- Model input and output contracts are documented.
- Structured outputs are validated before use.
- Model failure has a fallback.
- Human review exists before consequential external output.

## Portfolio integrity
- README does not claim production deployment unless true.
- Resume bullets describe actual implementation.
- User research and validation claims are traceable to real evidence.
- Architecture terminology is used only for features actually implemented.
